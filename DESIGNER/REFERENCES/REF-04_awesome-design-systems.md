# REF-04 — Awesome Design Systems (klaufel)

- **Source** : https://github.com/klaufel/awesome-design-systems
- **Ingéré** : 2026-09-24
- **Nature** : liste de référence sur les **design systems** : exemples, outils, jetons, bibliothèques de motifs, tests visuels, livres, conférences.

## Structure de la liste
1. **Design systems** (présentation, articles)
2. **Outils de conception** d'interfaces
3. **Design tokens** (gestion, validation)
4. **Pattern libraries** (développement de composants, guides de style)
5. **Tests** (régression visuelle, tests unitaires)
6. **Livres** · 7. **Conférences**

## Systèmes cités en exemple
Atlassian Design Guidelines · Firefox Photon · **GitHub Primer** · GitLab Pajamas · **Google Material Design** · **IBM Carbon** · **Shopify Polaris**.

## À retenir
- Un design system, ce n'est **pas une bibliothèque de composants**. Il réunit : des **jetons** (couleurs, espacements, typographie), des **composants**, des **règles d'usage** (quand utiliser quoi), une **documentation**, et un **contrôle** (tests visuels).
- ⚠ **Lacune constatée** : aucun design system **public ou gouvernemental** dans la liste. Pour des outils militaires ou étatiques, les références naturelles sont le **DSFR** (Système de design de l'État français), le **GOV.UK Design System** et l'**USWDS** ; **IBM Carbon** convient aux applicatifs de données denses. → **À faire ingérer** (question ouverte n°1, voir MEMOIRE).
