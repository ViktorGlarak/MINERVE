# Lecture du CODE SOURCE — Cognee et Model Context Protocol

> Veille du 2026-10-12. Clones locaux `topoteretes/cognee` (`R\` = `cognee\cognee\`) et `modelcontextprotocol/modelcontextprotocol` (schéma 2025-11-25). Complète REF-04 et REF-09.

## En bref
Cognee contient **quatre mécanismes utiles pour une mémoire d'agent** : des poids appris par feedback ; l'oubli par retour vers le neutre, **sans horloge** ; la distillation de session en deux passes (curateur puis rédacteur) ; la mise à l'écart d'un fait périmé par un fait plus récent (« supersession ») **sans rien supprimer**. Il n'y a pas d'oubli par suppression (sauf préférence sous 0,01). MCP n'apporte rien au moteur ; il sert à brancher Claude Code sur les données.

## A. Cognee
1. **Types de recherche** (`R\modules\search\types\SearchType.py`) : SUMMARIES, CHUNKS, RAG_COMPLETION, HYBRID_COMPLETION, TRIPLET_COMPLETION, GRAPH_COMPLETION (+ variantes), CYPHER, NATURAL_LANGUAGE, **TEMPORAL**, CODING_RULES, AGENTIC_COMPLETION, CODE, GRAPH_REPORT, SKILLS. Documentaire : CHUNKS, SUMMARIES, CYPHER, CODE, GRAPH_REPORT. Réutilisables : GRAPH_COMPLETION, TEMPORAL.
2. **Extraction de graphe** (`R\infrastructure\llm\prompts\generate_graph_prompt.txt`) : un appel par chunk en sortie structurée ; types élémentaires imposés (« always label it as "Person"… Don't use too generic terms like "Entity" ») ; **le temps est un nœud feuille « Timestamp »** (`YYYY`, `YYYY-MM`, `YYYY-MM-DD`) relié par `{verb}_at` / `{verb}_during` (« If a concrete node can carry the time, do not invent an Event ») ; coréférence par l'identifiant le plus complet ; TEMPORAL_NORMALIZATION_HINTS (dates relatives → absolues).
3. **Graphe d'événements** (`R\tasks\temporal_graph\*`, `generate_event_graph_prompt.txt`) : `Event{name, description, time_from, time_to, location}` + entités ; règle « ANY action or verb represents an event… Quantity over filtering… easily reaching a hundred events » — structure d'une mémoire épisodique, granularité trop fine pour nous.
4. **Recherche TEMPORAL** (`R\modules\retrieval\temporal_retriever.py:86-175`) : un LLM extrait l'intervalle de la question avec « Current date is: {{ time_now }} » injecté (« before 2009 → starts_at: None, ends_at: 2009 » ; sans date → jusqu'à maintenant) ; filtre des nœuds Timestamp ; reclassement vectoriel top_k 5 ; repli sur les triplets. Transposable (« qu'as-tu fait la semaine dernière ? »).
5. **Poids appris par feedback** (`R\tasks\memify\apply_feedback_weights.py:69-84`) : note 1-5 → `r=(note−1)/4` ; chaque élément utilisé reçoit **`w ← w + α(r − w)`**, α = **0,1**, feedback implicite à demi-α, idempotence par ligne, poids initial 0,5. Classement (`CogneeGraph.py:440-511`) : distance × `(2 − importance_weight)`, `d_eff = 2·[(1−inf)·d/2 + inf·(1−w)]`, somme sur nœud1 + nœud2 + arête ; `DEFAULT_FEEDBACK_INFLUENCE = 0.0` (désactivé sans réglage).
6. **Oubli sans horloge** (`R\modules\user_preferences\weights.py:10-38`) : **`w_eff = 0,5 + (w − 0,5)·(1 − β)^idle`**, idle = tours sans mise à jour, calculé **à la lecture** ; α = 0,3, β = **0,02** ; facteur de classement `1 ∓ influence·(2w − 1)`, influence 0,3 (± 30 % max) ; suppression sous **0,01**. Le seul vrai mécanisme d'oubli ; se transpose en « affinité avatar ↔ sujet ou personne ».
7. **Mémoire de session** (`feedback_detection_system.txt`, `session_context_builder.py:66-160`) : à chaque message, un appel JSON extrait ≤ 3 consignes durables (goals / rules / preferences / lessons_learned, « include only candidates with confidence >= 0.75 ») et note les entrées servies au tour précédent helpful / harmful (« Do not guess. If unclear, omit the rating ») ; **ranker déterministe sans LLM** : `10·section + 5·confiance + 4·recouvrement + 2·net_help + 1·priorité + 0,5·récence`, `NET_HELP_CLAMP = 3`, conflit → « prefer the later item ». Profil AGENT : failure_lessons, tool_rules, environment_facts, workflow_state, success_patterns.
8. **Distillation de session → mémoire durable** (`R\modules\session_distillation\distill.py`) = la consolidation : LOAD (net_help ≥ 0, confiance ≥ 0,75) → **CURATE** (lots de 16 000 caractères, 6 blocs, Q/R tronquées à 1 200 ; un LLM curateur propose des leçons : « MERGE… into ONE lesson », « DURABLE ONLY… Omit session-local trivia », « GROUNDED… do not promote a claim that exists only in an assistant answer unless the user or a candidate backs it ») → **ACCEPT** (5 leçons existantes les plus proches + 20 entités ; un LLM rédacteur : « accept=false, reason="already_known" | "not_durable" | "unsupported" », « never paraphrase, shorten, or rename a glossary entity », « why_learned: one short sentence naming the situation it was learned in ») → PERSIST (cognify, node set `session_learnings`) ; **le watermark n'avance pas si un appel échoue**.
9. **Leçons des traces d'outils** (`agent_context_extraction_system.txt`, `agent_memory/decorator.py`) : ≤ 5 leçons par lot, « EXISTING LESSONS: … Do NOT repeat or reword these » ; décorateur `@agent_memory(memory_top_k=5, session_memory_last_n=5…)`.
10. **Contradictions** : détection LLM (`detect_contradictions_system.txt`, paires avec raison et confiance, « cannot both be true at the same time about the same subject », pas les paraphrases ni compléments, seuil **0,5**) ; **supersession sans LLM** (`R\tasks\graph\resolve_temporal_contradictions.py`) pour les seules relations **fonctionnelles** (valeur unique : « CEO actuel ») : la plus récente l'emporte, les anciennes marquées `superseded / superseded_by / supersession_reason`, **rien n'est supprimé** ; identifiants déterministes (`Entity:<name>`).
11. **Pipeline « improve »** (ex-memify, `R\modules\improve\stages.py`) : feedback_weights, persist_session_qa, persist_agent_traces, extract_agent_context, distill_sessions, update_user_preferences, build_truth_subspace, triplet_enrichment, global_context_index. Autres : `consolidate_entities` (fusion si cosinus ≥ **0,85**), `cross_connect_entities` (arêtes inférées si similarité ≥ 0,5, chevauchement IDF ≥ 0,2, confiance LLM ≥ 0,7 ; naissent avec un poids de **0,2** = méfiance par défaut), `consolidate_entity_details.txt` (« Do not mention documents, chunks, source text »).
12. **Sans intérêt pour nous** (documentaire) : chunks et `summarize_content`, ontologies RDF/OWL (cutoff 0,8), code graph, CODING_RULES, CYPHER, text-to-SQL, truth_subspace (k = 8), global_context_index, BM25 lexical, traduction, scraper, intégrations Slack / GitHub / Linear. Base par défaut PostgreSQL + pgvector ; alternatives Kuzu, LanceDB ; GLiNER local pour l'extraction, Ollama possible ; Apache 2.0.

## B. Model Context Protocol (`schema\2025-11-25\schema.ts`, 2 582 lignes)
JSON-RPC 2.0 avec état, poignée de main `initialize` / `initialized` ; primitives serveur **tools** (`tools/list`, `tools/call`, `inputSchema` JSON Schema), **resources** (list / read / subscribe), **prompts** ; primitives client : sampling (`createMessage`), roots, elicitation ; utilitaires ping / progress / cancel / logging / pagination / tasks ; transports **stdio** (recommandé) et Streamable HTTP avec OAuth ; licence MIT. **Pour un moteur Node.js qui appelle Ollama en JSON et lit eho / le social en HTTP avec une clé : rien** (une couche à état + négociation + JSON-RPC pour remplacer un `fetch` + JSON Schema déjà en place) ; Ollama ne parle pas MCP nativement. Seule idée interne : décrire chaque action d'avatar comme un tool `{name, description, inputSchema}` = déjà le format de function-calling d'Ollama. **Usage pertinent** : un petit serveur MCP stdio exposant « lire la mémoire d'un avatar », « chercher un épisode », « lire le fil » pour que **Claude Code** inspecte ou débogue (décision PLEIADE, avis CYBERSECU).

## C. Idées transposables au moteur d'avatars
1. Épisode = `Event{name, description, time_from, time_to, location}` + entités ; temps normalisé `YYYY-MM-DD` relié par `{verb}_at`.
2. Rappel temporel en deux temps : intervalle extrait de la question (date du jour injectée) → filtre par date → reclassement par le sens ; sans date, sens seul.
3. **Consolidation nocturne en deux passes** : curateur par lot (leçons durables, fusionnées, fondées) puis rédacteur (rejet already_known / not_durable / unsupported, réécriture avec noms exacts et `why_learned`) ; watermark seulement en cas de succès complet.
4. Seuil d'admission : confiance ≥ 0,75 et net_help ≥ 0 (borné ± 3).
5. **Poids par souvenir appris du feedback** : `w ← w + 0,1·(r − w)`, demi-pas pour un signal implicite (réaction, réponse, ignoré) ; classement = distance sémantique mêlée à `(1 − w)` selon une influence réglable.
6. **Oubli sans horloge** : `w_eff = 0,5 + (w − 0,5)(1 − 0,02)^tours_inactifs`, calculé à la lecture, suppression sous 0,01 — affinités avatar ↔ personne / sujet.
7. **Mettre à l'écart sans effacer** pour les relations à valeur unique (habite, travaille_chez, en_couple_avec) : le fait récent marque l'ancien `superseded` ; détection LLM pour le reste (seuil 0,5).
8. Profil de leçons d'agent (failure_lessons, success_patterns, environment_facts) injecté avant l'action ; ne pas répéter les leçons existantes ; ≤ 5 par lot.
9. Ranker de contexte déterministe (section, confiance, recouvrement, net_help, récence) ; conflit → la plus récente gagne.
10. Consolidation d'entités : fusion si cosinus ≥ 0,85 ; liens inférés avec confiance initiale basse (0,2) jusqu'à confirmation par l'usage.
