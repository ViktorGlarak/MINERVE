# Lecture du CODE SOURCE — Letta Code (ex-MemGPT, harnais TypeScript)

> Veille du 2026-10-12. Clone local `letta-ai/letta-code`, commit 271f119 ; `LC\` = racine. Le dépôt `letta` (serveur Python) est vide : les outils historiques `memory_replace / memory_insert / archival_memory_*` et les blocs `limit / read_only` **n'y sont pas** (ils sont dans `letta-ai/letta`, `letta/functions/function_sets/base.py`, `letta/schemas/block.py`). Letta Code les **remplace** par le « MemFS v2 » : la mémoire est un dossier Markdown suivi par git, modifié avec Bash/Edit puis commité, et le prompt est recompilé depuis HEAD. Complète REF-07 et REF-08.

## 1. Blocs « core » → fichiers racine du MemFS
- Chaque bloc `{label, value, description}` devient `<label>.md` avec frontmatter `name` + `description` (`LC\src\backend\local\initial-memory.ts:41-66`) ; `MEMORY.md` = index racine.
- Blocs par défaut (`LC\src\agent\prompts\`) : `persona.mdx` (« Who I am, what I value… This evolves as I learn and grow »), `human.mdx`, `project.mdx`, `style.mdx` (« Whenever the human reveals a preference that will be useful for later, I should store it here »). **`human_memo.mdx`** = gabarit d'observation : « If they'd be annoyed to repeat it later, keep it. » / « What do they care enough to mention twice. » / « Keep the signal that will matter later, not every detail. »
- Trois niveaux (`letta_root_memfs.md:26-35`) : fichiers racine toujours dans le contexte ; sous-dossiers avec leur `MEMORY.md` = mémoire différée (nom + description seulement) ; `skills/` = procédural.
- Prompt système : « Keep core memory lean. Do NOT write memories that are easily derivable from searching past conversations (recall) » ; « References as synapses… strengthen with use » ; « Updates should generalize across situations rather than simply recording individual events ».
- **Plafonds** (`memory-constraints.ts:302-308`, vérifiés par un hook pre-commit git) : 20 000 caractères par fichier, **65 536 pour tout le core**, profondeur 2 ; fichiers `readOnlyFiles` (globs) protégés ; le fichier de contraintes lui-même exige une approbation humaine. Message du hook : « Move non-core detail out of root Markdown and behind MEMORY.md indexes… Do not raise or disable these limits unless the user explicitly approves it. » Alerte au-delà de 30 000 tokens de prompt système.

## 2. Compilation dans le prompt (`system-prompt-compilation.ts`)
Lecture **depuis HEAD uniquement** (non commité = invisible) ; rendu `<label><description>…</description>contenu</label>` + `<memory>` (index + `<deferred-memory>`) à la place de `{CORE_MEMORY}`. Si HEAD change en cours de conversation : bloc `<memory_update>` « Treat the following freshly rendered memory context as authoritative from now on; where it conflicts with earlier memory context, this newer memory context wins. » ; « Editing memory does NOT change your behavior in the current turn… You are writing for your future self ».

## 3. Outil `Memory` : ouverture progressive
« open them progressively instead of guessing… Entries are listed most recently edited first, up to 10 per directory… Before acting on a person, project… that your memory index points to, open the matching memory rather than working from assumptions. » Date = dernier commit git ; tri par récence ; 10 entrées max ; description du frontmatter → **la récence est l'indice de saillance implicite**.

## 4. Rappel (recall) : l'historique brut, consultable, jamais modifié
BM25 local (`transcript-search.ts:317-370`, k1 1,2, b 0,75), phrases entre guillemets = filtres stricts (+2), **anti-écho** : la question en cours et les recherches précédentes × 0,1 ; filtres de dates. Pas de vectoriel en local (le cloud fait hybride + RRF). Sous-agent de rappel (« Needle + Expand » : chercher avec limit 5, puis élargir avant/après) ; « do NOT assume you have no knowledge about it — instead, jog your memory ».

## 5. Fenêtre de contexte : résumé récursif (`compaction.ts`)
Déclenchement avant l'appel si `tokens > fenêtre − min(16 384, 20 %)` (4 car ≈ 1 token). Mode `sliding_window` : évincer 30 % de la tête (+10 % par pas), coupure juste avant un message assistant, jusqu'à tenir sous 70 % ; repli mode `all`. **Récursif** : le résumé précédent est réinjecté dans le texte à résumer (« If there is a previous summary being evicted, please extract a concise version of the critical info from it »). Prompt : « 1. High level goals… 2. What happened… 3. Important details… Preserve identifiers verbatim… 4. Errors and fixes… 5. Lookup hints: … note the topic and key terms that could be used to find it in message history later. Write in first person as a factual record… under 300 words. » Garde-fous : retours d'outils tronqués à 2 000, résumé à 50 000, retronquage par le milieu 120k → 2k. **Prompts « compagnon »** (`compaction-prompt-patterns.md:37-121`) : Conversation themes, Important details (« inside jokes, recurring phrases »), **Tone and voice**, **User feedback**, **Emotional state** (« Flag anything relevant for continuity, care, repair, or future sensitivity »), Lookup hints ; « Be thorough enough that the user does not feel forgotten » ; répéter « Do NOT continue the conversation » en tête et en fin.

## 6. Agents « sleep-time » = la réflexion
- Déclencheurs : après chaque compaction (défaut), ou tous les **25 pas**, ou off ; évaluée en fin de tour ; **désactivée par défaut sous Windows** (`LETTA_ENABLE_WINDOWS_AUTO_REFLECTION=1`).
- Prompt `reflection-v2.md` (Bash + Edit seulement), 5 phases : Investigate → **Extract** (priorités : « 1. Mistakes and corrections 2. Preferences and patterns 3. New facts worth retaining 4. Contradictions 5. Reusable procedures » ; filtres : « Lasting or ephemeral? / Already captured? / Generalizable? … "User prefers short chapters with cliffhanger endings" is worth storing; "User edited chapter 3 paragraph 2 on Tuesday" is not… The raw conversation is already searchable — don't re-record it. / Temporal references? Convert any relative dates… to absolute dates ») → **Update** (« Identity preservation: Persona and behavioral files are load-bearing… Never rewrite them wholesale » / « Contradiction resolution: … fix the stale entry at the source. Do not append the new version alongside the old. » / « Archiving retired context: … ARCHIVE.md… Delete (don't archive) content the user asked to forget ») → Review (niveau racine / différé) → Commit git (rien changé = pas de commit ; « Few meaningful changes > many trivial ones »).
- Entrées : tranche « unreflected » depuis le curseur `reflected_through_message_id`, sinon relecture des **50 derniers tours** ; ≤ 150 000 caractères ; instantané de la mémoire ≤ 40 000.
- Multi-conversations « auto » : 5 requêtes hybrides fixes (« user corrections and preferences repeated mistakes recurring feedback », « long term facts about people projects workflows… ») ; score = 50 × recherche + (15 + min(tours non réfléchis, 10)) + récence 8/5/2 + sources (≤ 4) + taille + 8 conversation courante − 8 déjà réfléchie ; ≤ 30 candidats puis un LLM sélecteur en choisit ≤ 5 (« Treat summaries/descriptions as weak internal metadata, not confirmed facts »).
- Isolation : **worktree git privé**, fusion auto, `merge --abort` en cas de conflit et nouvel essai ; **le curseur n'avance que si l'état est merged ou no_changes** ; backoff 60 s doublé, plafond 30 min ; mode `explicit` = l'agent principal relit la proposition.
- Sous-agent `memory-v2` ponctuel : « Keep quoted factual corrections and constraints verbatim rather than generalizing them. Update existing entries rather than duplicating them… Reorganize… only when explicitly requested. »

## 7. MemFS : mémoire suivie par git
Commit = unité de consolidation ; HEAD = seule source de vérité ; `git log` = histoire de l'identité (« You may view their evolution with git log ») ; dépôts partagés entre agents. Oubli explicite : `ARCHIVE.md` (déclassement daté), suppression pure sur demande, déplacement racine ↔ différé. **Aucun score d'importance ni décroissance numérique** : l'importance est jugée par le LLM (priorités Extract), la saillance par la récence git et les plafonds de taille. « Memory Palace » : vue utilisateur (Overview / Needs Attention / Suggestions, ≤ 6 sections × 3), liste « Dismissed » jamais reproposée, routine proposée seulement si la demande s'est répétée ≥ 3 jours.

## 8. Idées transposables à notre moteur
1. Une passe nocturne LLM qui **réécrit** (en plus du code qui agrège) avec les 5 priorités et 4 filtres de `reflection-v2.md` → modifications du registre et du persona, pas un résumé de plus.
2. Contradictions **corrigées à la source** + `archive` daté ; distinguer « oublier sur demande » (suppression) et « déclasser » (archive).
3. Curseur `consolidated_through_message_id` + relecture des N derniers tours ; le curseur n'avance qu'en cas de succès.
4. Choisir quoi consolider : score récence 8/5/2 + similarité à des requêtes fixes (« corrections, préférences répétées, faits sur des personnes, moments émotionnels »), garder 5.
5. Mémoire à deux niveaux **bornée en caractères**, validateur qui refuse et dit « déplace le détail dans le niveau différé » : la taille comme pression d'oubli.
6. Descriptions d'une ligne + récence comme index (≤ 10 entrées) : pré-filtre avant bge-m3, et l'avatar peut « ouvrir » un thème.
7. Résumé glissant au gabarit « compagnon » (Tone and voice, Emotional state, inside jokes, Lookup hints) ; déclenchement à fenêtre − 20 %, éviction ~30 % de tête avant une réponse de l'avatar, résumé précédent réinjecté.
8. « Lookup hints » indexés dans bge-m3 pour retrouver les messages bruts.
9. Recherche hybride bge-m3 + BM25 (k1 1,2, b 0,75) fusionnés par RRF, **anti-écho × 0,1** sur la question en cours.
10. Dates absolues obligatoires à l'écriture.
11. **Identité protégée** : biographie fondatrice et contraintes en `readOnly` ; persona modifiable seulement par touches (« Never rewrite them wholesale », « Changes should be incremental to avoid complete loss of self »).
12. Versionner la mémoire de chaque avatar (git ou journal de diffs) : audit, retour arrière après une mauvaise nuit, « voir comment il a changé » ; consolider sur une copie puis fusionner.
13. Bloc `<memory_update>` faisant autorité si la consolidation tourne pendant qu'un avatar parle.
14. Critère de souvenir marquant façon `human_memo` : « If they'd be annoyed to repeat it later, keep it » / « mention twice » → compteur de mentions ≥ 2 promeut au registre.
15. Liste « Dismissed » : ce que l'utilisateur a dit de laisser tomber n'est plus reproposé.
