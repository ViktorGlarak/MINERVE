# REF-07 — Letta (ex-MemGPT) : agents à mémoire hiérarchique « style système d'exploitation »

- **Sources** : README https://github.com/letta-ai/letta (lu le 2026-10-12, fourni par l'utilisateur) ; papier Packer et al., *MemGPT: Towards LLMs as Operating Systems*, arXiv 2310.08560 (2023) ; docs.letta.com (pages mémoire et « sleep-time / dreaming », partiellement lisibles — les détails d'outils marqués *[connaissance de l'agent]* sont à revérifier).
- **Licence** : Apache 2.0. **Langages** : serveur Python (`letta server`), SDK TypeScript, installation npm. Bases : **Postgres ou SQLite**. Modèles : fournisseurs cloud et **locaux (Ollama, vLLM)**. Interfaces : terminal, appli de bureau, web, Slack / Telegram / Discord. Format d'export d'agent `.af` *[connaissance de l'agent]*.

## Ce que fait le projet
- **MemGPT (papier)** — analogie avec la mémoire virtuelle d'un OS : le **contexte principal** (ce qui est dans la fenêtre du LLM) et le **contexte externe** (hors fenêtre, en base). Le contexte principal a trois parts : **instructions système** (fixes) · **contexte de travail** (*working context*, **modifiable par le LLM lui-même** par appels de fonction) · **file FIFO** des messages récents. Mécanismes : **interruptions / événements** (messages, horloge — « heartbeat »), appels de fonction pour lire / écrire la mémoire, **résumé récursif** quand la file déborde, **avertissement de pression mémoire** (le modèle est prévenu qu'il doit ranger). Évalué sur : rappel profond (DMR), ouverture de conversation à partir des souvenirs, questions sur documents plus grands que la fenêtre, clés-valeurs imbriquées.
- **Letta** — trois niveaux : **core memory** = **blocs de mémoire** (chaînes avec étiquette, valeur, limite de caractères, description ; *[connaissance de l'agent]* : `read_only` possible) que l'agent édite avec des outils (`core_memory_append` / `core_memory_replace` ; v1 : `memory_insert`, `memory_replace`, `memory_rethink` = réécrire tout le bloc) ; **recall memory** = historique des messages, consultable (`conversation_search`) ; **archival memory** = passages vectorisés (`archival_memory_insert` / `search`). Les blocs **s'attachent / se détachent** et peuvent être **partagés entre plusieurs agents**.
- **Sleep-time agents / « Dreaming »** (docs) : des sous-agents d'arrière-plan « *review recent conversations, consolidate useful lessons, and update memory without interrupting your active work* », déclenchés après N pas de l'agent ou à la compaction du contexte. Principe : utiliser le **temps mort** pour ranger la mémoire (papier *Sleep-time Compute* *[connaissance de l'agent]*).
- Contradictions / oubli : à la charge de **l'agent lui-même** (il réécrit ses blocs) ; l'archive ne s'oublie pas ; pas de validité temporelle des faits.

## Ce que dit le CODE SOURCE (clone `letta-ai/letta-code` commit 271f119 — rapport `CODE-letta-code.md`, lecture par agent d'exploration transmise par NOYAU)
> ⚠ Le dépôt serveur `letta` n'était pas cloné : les outils `memory_replace / memory_insert / archival_memory_*` et les attributs `limit / read_only` des blocs **n'y sont pas** (ils vivent dans `letta-ai/letta`, `letta/functions/function_sets/base.py`, `letta/schemas/block.py`). Letta Code les **remplace par le « MemFS v2 »** : la mémoire est un **dossier Markdown versionné par git**, édité avec Bash/Edit puis commité ; **HEAD est la seule source de vérité** (non commité = invisible), le prompt est recompilé depuis HEAD, et un bloc `<memory_update>` fait autorité si la mémoire change en cours de conversation (« *this newer memory context wins* », « *You are writing for your future self* »).
- **Blocs → fichiers** : `persona.md` (« *Who I am, what I value… This evolves as I learn and grow* »), `human.md`, `project.md`, `style.md`, et le gabarit **`human_memo`** : « *If they'd be annoyed to repeat it later, keep it* » / « *What do they care enough to mention twice* » / « *Keep the signal that will matter later, not every detail* ». Trois niveaux : racine (toujours dans le contexte) · sous-dossiers différés (nom + description seulement, ouverts « progressivement », 10 entrées max, triés par **récence git = saillance implicite**) · `skills/` (procédural). Consigne : « *Keep core memory lean. Do NOT write memories that are easily derivable from searching past conversations* », « *Updates should generalize across situations rather than simply recording individual events* ».
- **La taille comme pression d'oubli** : plafonds vérifiés par un **hook pre-commit** — 20 000 car. par fichier, **65 536 pour tout le core**, profondeur 2 ; au-delà : « *Move non-core detail out of root Markdown and behind MEMORY.md indexes… Do not raise or disable these limits unless the user explicitly approves it* ». Fichiers `readOnly` (globs) protégeant l'identité.
- **Réflexion « sleep-time »** (`reflection-v2.md`, sous-agent Bash + Edit) : déclenchée après chaque compaction ou tous les 25 pas ; 5 phases Investigate → **Extract** (priorités : **1. erreurs et corrections 2. préférences et habitudes 3. faits nouveaux durables 4. contradictions 5. procédures réutilisables** ; 4 filtres : **durable ou éphémère ? déjà capturé ? généralisable ? dates relatives → absolues**) → **Update** (« *Identity preservation: Persona and behavioral files are load-bearing… Never rewrite them wholesale* » ; « *Changes should be incremental to avoid complete loss of self* » ; **« *Contradiction resolution: fix the stale entry at the source. Do not append the new version alongside the old* »** ; déclassement daté dans `ARCHIVE.md`, suppression pure **seulement sur demande**) → Review → Commit (rien changé = pas de commit). Entrée : tranche non réfléchie depuis un **curseur `reflected_through_message_id`**, sinon 50 derniers tours ; travail sur un **worktree git privé** puis fusion ; **le curseur n'avance que si fusion réussie ou rien à changer** ; backoff 60 s doublé.
- **Résumé récursif du contexte** (`compaction.ts`) : déclenché à **fenêtre − 20 %**, éviction de **30 % de la tête** (coupure avant un message assistant), **résumé précédent réinjecté** ; gabarit : buts · ce qui s'est passé · détails (identifiants verbatim) · erreurs et corrections · **« Lookup hints »** (termes pour retrouver le brut) ; < 300 mots, première personne. **Prompts « compagnon »** : *Conversation themes, Important details (inside jokes, recurring phrases), Tone and voice, User feedback, **Emotional state** (« flag anything relevant for continuity, care, repair, or future sensitivity »)*, « *Be thorough enough that the user does not feel forgotten* ».
- **Rappel** : BM25 local (k1 1,2, b 0,75), phrases entre guillemets = filtre strict, **anti-écho × 0,1** sur la question en cours et les recherches précédentes ; pas de vectoriel en local ; sous-agent « Needle + Expand ». **Aucun score d'importance ni décroissance numérique** : importance jugée par le LLM (priorités), saillance par la récence git et les plafonds.

## Ce qui est pertinent pour la psychologie des avatars
- **Le contexte de travail rédigé par l'agent** = le **récit de soi** (*self-narrative*, Conway — *à sourcer*) : la mémoire autobiographique n'est pas une liste de faits mais un **texte que la personne se raconte**, réécrit chaque jour, qui fait la cohérence d'un jour à l'autre (« depuis le témoin anonyme, je ne sais plus quoi penser de la FORCE ; j'évite Untergang »). Nos résumés par le code sont justes mais **impersonnels** ; la « pensée courte » (avis n°13) est l'amorce d'un dedans en première personne, mais elle ne survit pas au message.
- **Blocs partagés** = la **mémoire sémantique de camp** (doctrine §3.2, étape 3) : une base commune, en **lecture seule** pour les avatars, tenue par l'animation (EXPERT_INFLUENCE / ANALYSTE pays) — Letta confirme que c'est une structure à part, pas une copie dans chaque fiche.
- **Pression mémoire** = notre budget d'invite ; **heartbeat** = nos créneaux ; **résumé récursif** = notre consolidation (mais nous l'avons voulue **par le code**, déterministe et traçable — décision avis n°14, à garder pour les chiffres).
- **Sleep-time** : la nuit, nos avatars dorment et la Gemma est **inoccupée** — c'est le moment des traitements coûteux par avatar.

## À récupérer (idées précises)
1. **Un bloc « où j'en suis » (≤ 400 car.) rédigé par l'avatar lui-même, la nuit** : à la consolidation, **un** appel court (Gemma, `think: false`) reçoit l'ancien bloc + le résumé du jour produit par le code + les 3 variations d'opinion / croyance les plus fortes, et réécrit le bloc en première personne (`memory_rethink`). Garde-fous **par le code** : le bloc ne peut pas contredire les chiffres (si opinion FORCE > 20, interdit « je ne crois plus la FORCE » — contrôle lexical Q3), pas de proche hors fiche / registre (Q1), pas de « mots de la foule » (Q7) ; si le contrôle échoue, on garde l'ancien bloc. Placé dans l'invite **à la place** du résumé du jour. Coût : **105 appels courts par nuit**, pendant que la machine est libre. Gain : continuité de soi sur 7 jours, bascule racontée par l'intéressé, dedans ≠ dehors visible pour l'animation.
2. **Blocs partagés en lecture seule = bases de camp** : un bloc par camp / cohorte (≤ 600 car.), édité par l'animation, inséré dans l'invite des avatars du bloc ; l'avatar ne l'édite jamais. Variante Letta `read_only`. C'est la mémoire sémantique de l'étape 3, enfin structurée.
3. **Utiliser la nuit** (sleep-time compute) comme règle d'ordonnancement : tout traitement par avatar qui demande le modèle (bloc « où j'en suis », relecture des 5 relations les plus importantes en une phrase chacune — `memory_rethink` sur la relation) se fait **entre le coucher et 06 h**, jamais au fil.
4. **Le bloc « où j'en suis » se construit comme `reflection-v2`, pas comme un résumé** (code) : l'appel nocturne reçoit les **5 priorités** (corrections subies > habitudes et préférences > faits nouveaux durables > contradictions > façons de faire) et les **4 filtres** (durable ? déjà dans le bloc ? généralisable ? dates absolues) ; consigne **« modifie par touches, ne réécris jamais tout »** (identité : « *avoid complete loss of self* ») — le code refuse un bloc dont moins de 40 % des phrases sont reprises de l'ancien ; les éléments fondateurs (fiche eho : bio, foyer, métier, tempérament) sont **en lecture seule** et hors du bloc.
5. **Contradictions corrigées à la source, pas empilées** (code — contredit le choix « transition » de Mem0 OSS, REF-05) : pour le **registre**, on clôt l'ancien fait et on écrit le nouveau (déjà fait) ; la phrase de **transition** de Mem0 ne sert qu'au **récit** (bloc « où j'en suis »), jamais comme troisième fait. **Déclasser ≠ supprimer** : un fait clos va dans une liste `archive` datée du registre (lisible pour « avant, j'avais… »), la suppression n'existe que sur demande d'animation.
6. **Curseur de consolidation et calcul sur copie** (code) : `m.consolide_jusqua` existe ; ajouter que la réécriture nocturne du bloc se fait sur une **copie** et n'est **basculée que si les garde-fous passent** ; le curseur n'avance qu'en cas de succès (sinon rattrapage la nuit suivante, comme le « > 30 h » actuel).
7. **Critère `human_memo`** pour promouvoir un souvenir au rang de marquant ou un fait au registre : « *mentionné deux fois* » (compteur d'attestations, REF-06 idée 7) ou « *il serait agacé de devoir le répéter* » (un fait que l'avatar a dû redire à un interlocuteur) — complète le score `imp` sans le remplacer.
8. **Anti-écho au rappel** (code) : les souvenirs qui sont la publication en cours ou ses reprises × 0,1 (nous excluons déjà `relu` ; généraliser aux repartages du même texte).
9. **Gabarit « compagnon » pour le résumé du jour** (code) : ajouter au `resumeDuJour` du code deux champs **ton / voix** (registres employés) et **état émotionnel à retenir** (« à ménager / à réparer »), pour que le bloc nocturne ait de quoi parler de continuité, pas seulement de faits.
10. **Ne pas récupérer** : le serveur Letta (Python + Postgres, boucle d'outils à chaque pas = plusieurs appels par message × 105 avatars) ; la mémoire d'archive éditée par l'agent (notre marquant / rappel par le code est moins cher et traçable) ; laisser l'avatar **éditer ses chiffres** (opinions, relations) — l'écart texte / chiffre se corrige côté chiffre (règle avis n°4), pas en laissant le modèle réécrire les deux.
