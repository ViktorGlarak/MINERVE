# REF-06 — Zep / Graphiti (graphe de connaissances TEMPOREL : faits avec validité dans le temps)

- **Sources** : README https://github.com/getzep/graphiti et https://github.com/getzep/zep-js (lus le 2026-10-12, fournis par l'utilisateur) ; papier Rasmussen et al., *Zep: A Temporal Knowledge Graph Architecture for Agent Memory*, arXiv 2501.13956 (2025, version HTML lue).
- **Licence** : Graphiti Apache 2.0 (Python) ; SDK `zep-js` Apache 2.0 — mais **Zep** est la plateforme **commerciale** (moteur graphe propriétaire, « < 200 ms à grande échelle ») ; une *Community Edition* ancienne existe. Bases Graphiti : Neo4j, FalkorDB, Kuzu (déprécié), Amazon Neptune. Modèles : OpenAI, Anthropic, Gemini, Groq, et tout point `/v1` compatible OpenAI (**Ollama**, vLLM, llama.cpp) — le README avertit que le moteur « *relies heavily on LLM calls* » pour l'extraction et la déduplication.

## Ce que fait le projet
- **Trois sous-graphes emboîtés** (papier) : **épisodique** (les données brutes telles qu'ingérées — messages, texte, JSON — « flux de vérité fondamentale », chaque fait dérivé y renvoie) ; **sémantique** (entités + relations extraites) ; **communautaire** (grappes d'entités fortement liées, avec résumé).
- **Faits = triplets** (entité₁, type de relation, entité₂) + un texte `fact` « contenant toute l'information pertinente ».
- **Modèle bi-temporel** — quatre horodatages par fait : `valid_at` / `invalid_at` (**quand le fait était vrai dans le monde**) et `created_at` / `expired_at` (**quand le système l'a su / l'a retiré**). Les dates relatives (« hier », « depuis lundi ») sont converties en ISO 8601 à partir de l'horodatage de référence de l'épisode.
- **Contradictions : on invalide, on ne supprime pas** — « *invalidates the affected edges by setting their t_invalid to the t_valid of the invalidating edge* » ; un LLM compare les nouveaux faits aux faits existants pertinents (même paire d'entités).
- **Extraction** : entités depuis l'épisode + les 4 précédents (deux tours complets) ; **le locuteur est automatiquement une entité** ; résolution d'entité par cosinus + plein texte puis validation LLM ; dédoublonnage des faits limité aux mêmes paires d'entités.
- **Recherche hybride** : cosinus · BM25 (Okapi) · parcours en largeur à *n* sauts ; **reclassement** par RRF, MMR, cross-encoder, **nombre de mentions épisodiques** (fréquence) et **distance dans le graphe** depuis le nœud central (l'utilisateur).
- **Communautés** par propagation d'étiquettes, extension dynamique (nouveau nœud → communauté majoritaire chez ses voisins), résumé map-reduce.
- **Bloc de contexte rendu à l'agent** : « `FACT (Date range: from - to)` » + noms / résumés d'entités + résumés de communautés, 10 à 20 éléments.
- **Résultats** : DMR 94,8 % (MemGPT 93,4 %) ; LongMemEval +18,5 % de précision, latence −90 % par rapport au contexte complet.

## Ce que dit le CODE SOURCE (clone `getzep/graphiti` commit 0a3b1711 du 11/10/2026 — rapport `CODE-graphiti.md`, lecture par agent d'exploration transmise par NOYAU)
> Complète et corrige le papier : **plus de prompt `invalidate_edges` séparé** ; **le LLM juge, le code date.**
- **Contradiction** : le LLM ne rend que `{doublons, contredits}` (`dedupe_edges.resolve_edge`), avec un prompt **anti-faux positifs** : « *NEVER mark facts as contradicted unless the new fact explicitly makes the old fact false* », « *Do NOT infer contradiction from recency alone* », « *Do NOT treat additional activity, progress, status… as contradictions of role, ownership, membership* » ; exemples : « software engineer » → « senior engineer » = contradiction (titre mis à jour) ; « 5 miles mardi » / « 3 miles mercredi » = ni doublon ni contradiction. Aucun candidat → pas d'appel ; fait identique normalisé → on ajoute seulement l'épisode attestant.
- **La clôture est datée par une règle de chevauchement déterministe** (`edge_operations.py:715-783`) : nouveau fait déjà muni d'un `invalid_at` → historique ; **fait ancien raconté en retard** (candidat dont `valid_at` est postérieur au nouveau) → c'est le **NOUVEAU** qui est clos ; intervalles sans chevauchement → rien ; sinon `old.invalid_at = new.valid_at`, `old.expired_at = now`. **Rien n'est supprimé.**
- **Datation** : règles DATETIME dans le prompt d'extraction (présent → date de l'épisode ; futur / promesse → date de l'épisode, **jamais la date future** ; « d'ici mars » n'est pas une fin ; « jusqu'à » peut l'être) ; **garde-fou regex sur le futur** (`temporal_edge_utils.py`) qui ramène `valid_at` à la date de référence et efface un `invalid_at` d'échéance douce ; **datation séparée par un petit modèle, lots de 20, seulement pour les faits nouveaux sans date** (« *NEVER hallucinate dates… resolve relative expressions using REFERENCE TIME* »).
- **Entités** : nom exact → MinHash (trigrammes, 32 permutations, Jaccard ≥ 0,9) ; **refus du flou** sous 6 caractères, < 2 mots ou entropie < 1,5 (→ LLM) ; prompt : « *NEVER extract abstract concepts, feelings, or generic words* », parenté nue interdite (« Nisha's dad », pas « dad »), locuteur toujours premier nœud, « *When in doubt, do NOT extract* ».
- **Résumé évolutif d'un nœud sans LLM tant que ≤ 2 000 caractères** ; sinon 2-6 phrases avec « *Current state over superseded state* », « *NEVER manufacture pattern language from a single occurrence* », « *If the new episodes add no durable fact, return the existing summary unchanged* ».
- **Recherche** : cosinus min 0,6, BM25 ≤ 128 mots, BFS profondeur 3 ; **RRF avec k = 1** (`1/(rang+1)`, sans pondération) ; `node_distance` = en réalité **un seul saut** ; `episode_mentions` = tri par nombre d'épisodes attestant ; cross-encoder local possible (`BAAI/bge-reranker-v2-m3`). **Aucun filtre par défaut n'exclut les faits expirés** → il faut afficher les intervalles.
- **Coût** : ~3 appels + 1-2 par fait et par épisode (8 faits ≈ 12-20 appels), sortie structurée Pydantic « *particularly problematic when using smaller models* » ; **pas de mode sans base graphe** (tout en Cypher). Apache 2.0.

## Ce qui est pertinent pour la psychologie des avatars
- **La validité d'un fait n'est pas la date où on l'apprend** : « ma voiture est en panne depuis lundi » posté mercredi ⇒ vrai depuis lundi ; « j'ai hébergé ma sœur deux jours » ⇒ terminé. Sans cette distinction, l'avatar ne sait pas dire « ça fait trois jours » ni parler au passé d'un fait clos.
- **Invalider sans supprimer** = la bonne psychologie : un fait ancien reste un **souvenir** (« avant, j'avais une voiture ») ; une croyance démentie reste une croyance **passée** (« j'y ai cru deux jours »). C'est ce que `vie.mjs` fait déjà pour les faits de vie, pas `esprit.mjs` pour les croyances.
- **Le locuteur comme entité**, la **provenance** vers l'épisode (qui m'a dit quoi, quand) = la **vigilance épistémique** (Sperber 2010, *à sourcer*) : juger une information par sa source. Nos croyances gardent `sources[]` et `dementis[]` ; nos souvenirs gardent `auteur`.
- **Mentions épisodiques** comme signal de rappel = l'effet de répétition (vérité illusoire) appliqué à la **disponibilité** du souvenir ; **distance dans le graphe** = notre facteur `lien`.
- **Communautés** ≈ nos cohortes / camps — mais chez nous elles sont **données par les fiches**, pas découvertes ; inutile de les calculer.

## À récupérer (idées précises)
1. **Bi-temporalité du registre** : ajouter `dit_t` (quand il l'a dit = l'actuel `depuis_t`) et calculer **`depuis_t` à partir des marqueurs du message** — table fermée, sans modèle : « depuis lundi / mardi… » → jour de la semaine le plus proche en arrière ; « hier » → t − 24 ; « avant-hier » → t − 48 ; « ce matin » → début de journée ; « la semaine dernière » → t − 168 ; « depuis N jours » → t − 24N ; sinon `depuis_t = dit_t`. Les durées par défaut partent de `depuis_t`. De même le récit d'une fin (« réparée hier ») clôt à t − 24.
2. **Plages de dates dans l'invite** (le « FACT (Date range) » de Zep) : `blocVie` → « voiture en panne (**depuis lun., 3 j**) ; sœur hébergée (**mar. → jeu., terminé**) » ; ligne FAITS ACQUIS de la relecture idem. L'avatar peut alors dire « ça fait trois jours » et ne reparle pas d'un fait clos au présent (Q1/Q2 de l'avis n°13 deviennent vérifiables).
3. **Chronologie des croyances** : à partir de `historique[]`, donner à chaque croyance `periode = {cru_depuis: première exposition où crédence ≥ 50, cru_jusqua: démenti ayant ramené la crédence < 35, ou null}` ; `decrireCroyance` rend « tu y as cru du J1 14 h au J2 09 h, puis démenti par la préfecture ». La bascule et le retour d'Esteban (§4.4) deviennent **racontables par lui-même**. Coût : 0 appel.
4. **Mentions au rappel** : ajouter `+0,05·min(1, expositions/4)` au score S pour les souvenirs liés à une croyance répétée (effet de disponibilité). À essayer après 1-3.
5. **« Le LLM juge, le code date »** (code) : dans l'appel d'extraction de `vie.mjs`, ne demander au modèle que `{même_fait: [idx], contredit: [idx]}` parmi les faits actifs proches (candidats trouvés par le code : même clé ou cos ≥ 0,80), avec le prompt anti-faux positifs en français et ses trois exemples (« employé » → « chef d'équipe » = changement ; « 5 km mardi » / « 3 km mercredi » = rien ; « ne pas déduire une contradiction de la seule date »). Puis **la règle de chevauchement en JS** : ancien fait raconté en retard → le **nouveau** est clos (« la semaine dernière ma voiture était en panne » ne rouvre pas une panne réparée) ; sinon l'ancien se clôt à `depuis_t` du nouveau. Coût : 0 appel de plus (même appel), robuste aux petits modèles si l'on exige « EXACTEMENT n indices 0..n−1, −1 si doute ».
6. **Garde-fou regex du futur** (code) : « va / compte / prévoit / promet / -ra » → `depuis_t = dit_t` et pas la date future (une promesse n'est pas un état) ; « avant le / d'ici » ≠ fin ; « jusqu'au / ne plus / fini » = fin. 0 appel.
7. **Compteur d'attestations** : fait identique normalisé → `nb_attestations++` (pas de doublon) ; sert de bonus au rappel (`episode_mentions`) et de critère « mentionné deux fois » pour promouvoir au registre (rejoint REF-07 `human_memo`).
8. **Résumé de relation sans LLM** tant qu'il tient (code) : notre `resumeRelation` (160 car.) est déjà dans cet esprit ; si une version rédigée par le modèle est un jour voulue (REF-07), appliquer ses trois règles : état courant d'abord, pas de « tendance » tirée d'une seule occurrence, inchangé si rien de durable.
9. **Ne pas récupérer** : le graphe (Neo4j/FalkorDB), la résolution d'entités et l'invalidation **par LLM** (plusieurs appels structurés par épisode — impossible pour 105 avatars sur une seule Gemma, et les petits modèles tiennent mal les sorties structurées exigées), les communautés calculées, Zep Cloud (données hors site : exclu).
